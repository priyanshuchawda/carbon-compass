## Project idea: **Carbon Compass — Personal Carbon Footprint Awareness Platform**

Build a **real working website** where users can calculate their carbon footprint, understand which habits create the most emissions, and get small personalized actions to reduce it.

The winning angle should be: **not just a calculator — a smart assistant that explains, compares, and gives action plans.**

Reliable grounding matters. EPA’s household carbon calculator focuses on household emissions estimation and reduction actions, while GHG Protocol is widely used for emissions accounting methods and calculation guidance. For accessibility, use WCAG 2.2 as your target standard. ([US EPA][1])

---

# 1. Chosen vertical

Choose this vertical/persona:

**Urban student / young professional in India**

Why this is strong:

Most hackathon projects become generic. This one becomes specific and practical.

Persona example:

> “A student or young working person living in a city like Pune, using bike/metro/cab, ordering food, using electricity, buying gadgets/clothes, and wanting simple climate-friendly choices without complex environmental jargon.”

This fits the challenge because the product helps individuals **understand, track, and reduce** their footprint through small actions.

For India-specific electricity calculations, you can keep an emission factor source table. India’s Central Electricity Authority baseline database reports grid electricity emission factors, including a weighted average factor of about **0.710 tCO₂/MWh for FY 2024–25**, which can be converted to **0.710 kg CO₂/kWh** for simple app calculations. ([Central Electricity Authority][2])

# 4. Carbon calculation logic

Use simple activity-based calculation.

\text{Emissions}_{kgCO_2e}=\text{Activity Amount}\times\text{Emission Factor}

Example:

```txt
monthlyElectricityCO2 = electricityKWh * electricityEmissionFactor
weeklyBikeCO2 = bikeKm * petrolTwoWheelerFactor
foodCO2 = dietTypeBaseFactor + deliveryFrequencyFactor + wasteFactor
```

Important: do not pretend calculations are perfect. In README, write:

> “This is an educational estimate, not an audited carbon inventory. Emission factors are stored with source names and can be updated.”

This makes the project honest and professional.

# 5. Smart assistant feature

This is where your project becomes “dynamic assistant,” not just forms.

## Assistant name

**Compass Assistant**

## What it does

After user enters data, assistant explains:

* Your biggest emission source
* Why it is high
* 3 easy actions
* Expected monthly reduction
* Difficulty level
* Money-saving possibility
* Weekly challenge

Example output:

> “Your biggest footprint source is transport because you travel 140 km/week by petrol scooter. Try replacing 2 short trips per week with walking, cycling, or metro. Estimated saving: 4–8 kg CO₂/month.”

## Assistant logic

Use rule-based logic first, AI second.

Strong architecture:

```txt
User data
   ↓
Carbon calculation engine
   ↓
Ranking engine: highest emission categories
   ↓
Recommendation rules
   ↓
Optional AI explanation rewrite
   ↓
Personalized action plan
```

This is better than directly sending everything to AI because it is safer, testable, and explainable.

# 10. Recommendation engine logic

Do not make random recommendations. Use deterministic rules.

Example:

```ts
if (transportCO2 > totalCO2 * 0.35) {
  recommend({
    title: "Replace 2 short fuel trips per week",
    category: "transport",
    difficulty: "easy",
    reason: "Transport is your largest footprint category.",
    estimatedSavingKgPerMonth: 5,
  });
}
```

More rules:

```txt
If electricity is high:
  suggest AC optimization, LED usage, unplugging idle devices.

If food footprint is high:
  suggest one low-carbon meal day, reduce food waste, plan meals.

If shopping is high:
  suggest monthly no-buy week, repair/reuse, combine deliveries.

If waste is high:
  suggest recycling, composting, reusable bottle/bag.
```

This satisfies **logical decision making based on user context**.

# 12. Security plan

For evaluation, clearly mention:

* Validate all inputs using Zod.
* Never trust client-side calculation only.
* Use server-side calculation for final results.
* Add rate limiting to APIs.
* Do not store unnecessary personal data.
* Store only approximate lifestyle data.
* No exact home address required.
* Use environment variables for API keys.
* If AI is used, do not send sensitive user data unnecessarily.
* Add clear disclaimer: estimates are educational.

Example:

```txt
We only ask for city-level location, not exact address.
Carbon calculations are estimates and not used for legal/compliance reporting.
```

This will score well in **security**.

# 13. Efficiency plan

Mention:

* Carbon factors are loaded from local JSON.
* Calculation is O(n) over categories.
* Recommendations are rule-based and fast.
* Charts render from already-calculated summary.
* Cache static emission factor data.
* Avoid unnecessary AI calls.
* AI explanation is optional, not required for calculation.

# 16. README structure

Your README should look like this:

```md
# Carbon Compass

Carbon Compass is a personal carbon footprint awareness platform that helps urban students and young professionals understand, track, and reduce their lifestyle emissions through simple actions and personalized insights.

## Chosen Vertical

Urban students and young professionals in India.

## Problem

Most people want to reduce their environmental impact but do not know which daily habits matter most. Existing information is often too technical, generic, or guilt-driven.

## Solution

Carbon Compass calculates an estimated monthly carbon footprint across transport, energy, food, shopping, and waste. It identifies the user’s highest-impact category and gives simple personalized actions.

## Key Features

- Carbon footprint calculator
- Personalized dashboard
- Category-wise breakdown
- Smart recommendation engine
- Weekly action plan
- What-if simulator
- Progress tracking
- Accessible and mobile-first UI

## Approach and Logic

The system uses activity-based estimation:

Emissions = Activity Amount × Emission Factor

The app ranks categories by impact and recommends actions based on the user's highest emission sources.

## Assumptions

- Calculations are educational estimates, not certified carbon accounting.
- Emission factors are configurable and versioned.
- Users provide approximate lifestyle data.
- City-level location is enough; exact address is not required.
```
